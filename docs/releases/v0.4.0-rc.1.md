# Playtestr v0.4.0-rc.1 release notes

Status: **kit ready, publication pending**. These notes describe qualified
candidate bytes; the tag, GitHub release, public downloads, and setup-action
revision do not exist yet.

This prerelease adds opt-in specification version 2 workspaces: every run can
copy a bounded reviewed fixture and receive managed home and temporary
directories. V2 and mixed suites emit report version 2 so setup, primary test,
and cleanup outcomes stay distinct. All-v1 suites retain report v1 and existing
v1 terminal/action semantics.

It also includes exact-version setup-action source, stronger transactional
installation failure handling, complete v1/v2 offline HTML rendering, three
copyable recipes, and native archive/terminal hardening. The qualified corpus
contains 120 workflows across 15 pinned applications; that is technical
operator evidence, not maintainer endorsement or independent adoption.

## Compatibility and limits

- Specs: v1 and v2. V2 requires `workspace`; no v1 behavior changes implicitly.
- Reports: all-v1 suites write v1; v2 or mixed suites write v2. The candidate's
  HTML renderer reads both.
- Previous `v0.3.0-rc.1` passes the reviewed v1 menu flow and diagnoses its
  intentional mismatch; it does not support v2 workspaces.
- Targets execute with the user's permissions. Playtestr is not a sandbox.
- Compatibility is scoped by exact project/version/host/workflow evidence. No
  universal framework, Unicode, accessibility, or zero-flakiness claim is made.
- Target-rendered secrets can appear in reports and snapshots. Review fixtures
  and retained evidence; automatic redaction is not promised.
