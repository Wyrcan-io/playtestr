# Playtestr v0.1.0

Playtestr v0.1.0 is the first stable release of the standalone runner for
deterministic end-to-end tests of trusted interactive CLIs and TUIs.

## What is included

- Drive a real pseudoterminal with text, named keys, resize, and redraw waits.
- Assert rendered text, disappearance after interaction, exact exit status, and
  reviewed normalized text snapshots.
- Bound step/run time and raw output; cancel with exit 130 and clean up the
  managed process tree.
- Write atomic machine-readable report v1 plus bounded screen/diff evidence.
- Run without Go from a native Linux amd64, macOS arm64, or Windows amd64 archive.

Stable means these documented workflows and formats passed the release gates
and will be maintained under [`SUPPORT.md`](../../SUPPORT.md). It does not mean
every terminal, framework, OS release, architecture, or Unicode layout works.

## Changes from the release candidates

The stable bytes contain the rc.2 behavior without a post-candidate product-code
change. Compared with rc.1, Unix targets receive a controlling terminal,
`expect_not` cannot pass before prior observation and interaction,
`wait_for_redraw` synchronizes resize flows, and failure screens are captured
before cleanup restores an alternate screen. The stable release workflow also
tests cancellation against each extracted native binary.

Spec and report versions remain 1. Existing rc.1 and rc.2 specs remain valid.
For an unversioned prototype spec, add top-level `"version": 1`; see the
[contract audit](v0.1.0-contract-audit.md) and [`CHANGELOG.md`](../../CHANGELOG.md).

## Known scope

- Styled snapshots and precise grapheme, emoji, combining-mark, and East Asian
  wide-character cell layout are outside the version 1 contract.
- Windows has a small launch-to-Job-Object attachment window; Unix descendants
  can deliberately detach into another session.
- Playtestr executes trusted targets with the user's permissions. It is not a
  sandbox, and a target can print sensitive information into screen evidence.
- Nine pinned cross-stack applications passed operator-run Windows and WSL Linux
  workflows. That evidence is not independent adoption or universal framework
  certification.

Use the [stable installation walkthrough](https://wyrcan-io.github.io/playtestr/docs/installation/)
for a binary-only first test and the [support page](https://wyrcan-io.github.io/playtestr/support/)
to diagnose or report a problem.
