# v0.1.0 public-contract audit

Status: complete for the stable-source candidate on 12 September 2026. The
stable asset hashes and workflow links are recorded separately after native
build and public-download verification.

## Contract parity

The README, CLI help, spec/report documentation, JSON Schemas, implementation,
and tests agree on the following frozen boundary:

| Area | Stable v0.1.0 disposition |
| --- | --- |
| Versions | A spec requires integer `version: 1`; reports emit `report_version: 1`. Missing, null, non-integer, and unsupported spec versions are rejected before launch. |
| Unknown and empty values | Unknown spec/step fields and multiple step actions are rejected. `command` and `steps` require at least one item; action strings that need content reject empty strings. Optional values are omitted, not represented as null. |
| Defaults | Viewport `80x24`; step timeout 3,000 ms; run timeout 30,000 ms; raw output 2,000,000 bytes; startup timeout disabled when omitted or zero. |
| Limits | Specs 1 MB/1,000 steps; viewport 500x200; step/startup 120 s; run 1 h; output 1 GB; 100 snapshots; each snapshot 2 MB/10,000 lines; staged updates 16 MB; diff 256 KiB; report 8 MiB. |
| Paths | Relative `cwd` and snapshot paths resolve from the spec directory; omitted `cwd` preserves the invocation directory. Snapshot names cannot contain slash, backslash, or colon. Reports and evidence use atomic local writes. |
| Exit statuses | `0` all pass, `1` test/evidence/report failure, `2` CLI usage, `130` interrupted run. An `exit` step requires the exact declared code from 0 through 255. Unknown target exit remains `exited: false` with no `exit_code`. |
| Snapshots | Rendered text, not ANSI bytes; LF endings; leading/internal space retained; trailing spaces and unused rows removed; final newline required. Styles and precise complex-Unicode cell layout are excluded. |

No public-contract disagreement required a behavior change. Spec v1 is frozen
for compatible additions; incompatible meaning requires a new version and
migration notes.

## Release-critical path review

| Review target | Evidence and disposition |
| --- | --- |
| Late cancellation before baseline writes | Deterministic tests cancel after a staged snapshot and immediately after the final step; neither commits a baseline. |
| Failed baseline commit | Updates are staged, originals retained, writes are atomic, and a failed multi-file commit rolls back already changed files. An unrestoreable path is reported explicitly rather than claimed clean. |
| Cleanup errors | Cleanup has its own report object/failure. It is joined to, not substituted for, the primary failure; cleanup-only failure fails the run. |
| Report-write failure | Atomic report writes return exit 1 and print `FAIL write report`; no success claim is emitted for the requested report. |
| Size bounds | Raw output, snapshots, staged updates, diffs, specs, and reports have explicit limits tested at their relevant boundary. |
| Unknown exit status | The report omits `exit_code` unless known; no sentinel code is invented. |
| Secret boundary | Reports omit commands, environment names/values, typed/expected text, and screens. Screens/diffs can contain target output and are documented as sensitive user-reviewed files. |
| Expected-failure CI | Both terminal CI and native packaging require exit 1. Native packaging additionally requires `snapshot_mismatch`, the exact screen/diff paths, and nonempty files. |
| Extracted-byte cancellation | The native release workflow signals the extracted binary, requires exit 130 and `cancelled`, and requires confirmed target cleanup on every supported native host. |

The audit found and closed the missing extracted-byte cancellation gate in the
native release workflow. No false-pass, destructive failure, dependency-notice,
or unresolved security blocker remains in the reviewed source candidate.
