# Playtestr v0.1.0-rc.2 release notes

Status: published 9 September 2026 from commit `583352ad381df15f0fda652dae9ef819f5f24c9a` after native packaging and extracted-archive checks passed.

## What changed

- Unix targets now receive the PTY slave as their controlling terminal. This fixes full-screen applications such as Lazygit that open `/dev/tty`; the rc.1 Linux binary exits during that path.
- `expect_not` waits for text that was positively observed earlier to leave the rendered screen after input or resize. This prevents stale background text from advancing modal workflows.
- `wait_for_redraw` requires post-resize output and allows a bounded one-second redraw window before subsequent input. It supports continuously repainting dashboards that never reach an output-quiet state.
- Failure artifacts retain the rendered screen observed before process cleanup, so alternate-screen restoration cannot erase useful evidence.
- Trial recipes can combine the unchanged Playtestr report with an independent external oracle and preserve both outcomes.

The spec and report schema versions remain 1. Existing specs remain valid. The new actions are additive.

## Known scope

- Lazydocker v0.25.2 on Linux is not claimed to support reopening help after a live resize to 80x24. Normal 120x40 help and resize-only paths remain usable in the tested environment.
- Some Lazydocker endpoint failures and K9s denied/unreachable API states render no useful terminal diagnostic. Playtestr reports the bounded assertion or exit outcome and preserves any screen available before cleanup.
- Precise grapheme, emoji, combining-mark, and East Asian wide-character cell layout remains outside the current terminal-emulator contract.
- Playtestr runs explicitly trusted targets with the user's permissions; it is not a sandbox.
