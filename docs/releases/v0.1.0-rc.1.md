# Playtestr v0.1.0-rc.1

This is Playtestr's first release candidate: a standalone runner for deterministic end-to-end tests of trusted interactive CLIs and TUIs.

## What it can do

- Launch a target in a real pseudoterminal and send text, arrow keys, Enter, Escape, Tab, Backspace, and Ctrl+C.
- Assert rendered terminal text, exact process exit status, and reviewed text snapshots.
- Resize the terminal and test redraws.
- Produce bounded unified diffs, final-screen evidence, and a versioned JSON report.
- Bound step/run time and raw output, cancel cleanly, and stop the managed process tree on supported hosts.

The test specification and machine report are both version 1. This release is intended for explicitly trusted local targets; PTY process execution is not a sandbox.

## Downloads

Choose exactly one archive:

| Host | Archive |
| --- | --- |
| Linux amd64 | `playtestr_0.1.0-rc.1_linux_amd64.tar.gz` |
| macOS arm64 | `playtestr_0.1.0-rc.1_darwin_arm64.tar.gz` |
| Windows amd64 | `playtestr_0.1.0-rc.1_windows_amd64.zip` |

Download the archive and its adjacent `.sha256` file from this release. From the download directory, verify it before extraction:

```sh
sha256sum --check playtestr_0.1.0-rc.1_linux_amd64.tar.gz.sha256
tar -xzf playtestr_0.1.0-rc.1_linux_amd64.tar.gz
./playtestr_0.1.0-rc.1_linux_amd64/playtestr --version
```

On macOS, use `shasum -a 256 playtestr_0.1.0-rc.1_darwin_arm64.tar.gz` and compare the printed value with the checksum file, then extract with `tar`.

```powershell
$archive = 'playtestr_0.1.0-rc.1_windows_amd64.zip'
$expected = (Get-Content "$archive.sha256").Split()[0]
$actual = (Get-FileHash $archive -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw 'Playtestr archive checksum mismatch' }
Expand-Archive $archive -DestinationPath .
& '.\playtestr_0.1.0-rc.1_windows_amd64\playtestr.exe' --version
```

The version command must print `playtestr v0.1.0-rc.1`. Copy the binary to a directory on `PATH` if desired. Removing that binary removes Playtestr; the runner does not install services or global configuration.

## First binary-only test

Playtestr does not install your target application. The following uses a shell already present on the host as a small trusted interactive target. Create the two files for your platform in an empty directory.

On Linux or macOS, create `hello.sh`:

```sh
#!/bin/sh
printf 'Name: '
IFS= read -r name
printf 'Hello, %s!\n' "$name"
```

Make it executable with `chmod +x hello.sh`, then create `hello.json`:

```json
{
  "version": 1,
  "name": "shell greeting",
  "command": ["./hello.sh"],
  "steps": [
    {"expect": "Name:"},
    {"text": "terminal tester"},
    {"key": "Enter"},
    {"expect": "Hello, terminal tester!"},
    {"exit": 0}
  ]
}
```

On Windows, create `hello.ps1`:

```powershell
$name = Read-Host 'Name'
Write-Host "Hello, $name!"
```

Then create `hello.json` with `command` set to `["powershell.exe", "-NoProfile", "-ExecutionPolicy", "Bypass", "-File", "./hello.ps1"]` and the same steps shown above. Run it with the extracted Playtestr binary:

```text
playtestr test --report results.json hello.json
```

After it passes, change the final expected text to `Hello, wrong!`. The command should exit 1, save a final screen beside the spec, and write the failure to `results.json`. Restore the assertion and rerun to return to a passing test.

## Demo from source

The interactive mission-control demo is not included in release archives. It requires Git and Go 1.25 or newer:

```sh
git clone --branch v0.1.0-rc.1 --depth 1 https://github.com/Wyrcan-io/playtestr.git
cd playtestr
go build -o bin/demo ./cmd/demo
go build -o bin/playtestr ./cmd/playtestr
./bin/playtestr test examples/menu.json examples/menu-exit.json
```

On Windows, add `.exe` to the two output names and invoke `./bin/playtestr.exe`.

## Current limitations

- On Linux, this release does not assign the PTY slave as the target session's controlling terminal. A full-screen application that opens `/dev/tty` directly can fail at launch. This is fixed in current source and will require a replacement release candidate before the published path can be claimed compatible.
- Text snapshots ignore styling and do not model wide-character, combining-mark, grapheme-cluster, or emoji cell width correctly.
- Windows Job Object attachment has a narrow post-launch window in which an unusually early child could escape. Unix descendants can deliberately detach into another session.
- Terminal compatibility is bounded by the documented emulator contract; one successful application does not imply framework-wide compatibility.
- The runner inherits only a restricted operational environment plus values explicitly selected in a spec. A target can still print secrets into captured terminal evidence.

See the version-matched [README](../../README.md), [spec v1](../spec-v1.md), [report v1](../report-v1.md), [terminal compatibility](../terminal-compatibility.md), and [platform evidence](../platform-support.md). Report problems through [GitHub Issues](https://github.com/Wyrcan-io/playtestr/issues) with the runner version, host, target version, a minimal spec, and sanitized evidence.
