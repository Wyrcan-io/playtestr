# P0: Go recorder and PR execution contracts

Accepted for the P0–P2 batch, 7 October 2026. Source baseline e9491ad. This execution is explicitly authorized by the invoked [batch prompt](../plans/p0-p2-full-implementation-prompt.md), superseding the earlier planning-only boundary for P0–P2. P3/P4 remain design only.

Reuse audit: strict spec parser, rendered-screen session, bounded lifecycle, fixture copier, snapshot staging, suite discovery, reports and installer already exist. Recorder lives beside runner internals and calls the same step executor and fresh runner; CLI owns control input/review. A small native console adapter handles operator input/restoration, not target VT parsing. No target framework dependency, another execution language or new public test action/version is introduced. Candidate steps and baseline text are memory-only; private runner options accept reviewed candidate data for replay without saving drafts. Export remains strict v1/v2. Existing releases, schema versions and manual authoring remain intact. The acceptance harness independently inspects actual wizard file bytes before workspace cleanup; it does not rely solely on the target's success marker.

Controls: a distinct line console plus `/live`; Ctrl+G escapes live mode, literal Ctrl+G is explicitly sent using `/text "\u0007"`. No silent unhandled keys. Command console edit/delete/move and fresh prefix rerecord supply the maintenance contract. Exact text/disappearance/exit checkpoints express developer intent. Unique/nonstale anchors and existing snapshot readiness rules prevent quiet-only authoring. Full-screen output is rendered text; combining/ZWJ/style/query limitations remain the existing terminal boundary. Interrupted/error export rolls back reserved new files; power-loss/concurrent local writers are outside that runtime atomicity promise. Fixtures are bounded, rehashed and copied fresh; stateful demo's file readback happens before cleanup. General external-state oracles remain existing harness responsibility, not an invented inferred assertion.

Free PR contract: GitHub merge checkout by default, with distinct PR head/base and tested SHA, exact pinned runner/helper source or runner release, context manifest v1 bounded to 256 KiB, 1,000 inventory items/128 MiB hashing, ordinary report v1/v2 and customer-owned artifacts. Missing selection, identity, report or cleanup never implies success. Superseded runs cancel rather than retry. Explicit bash build/prerequisite commands remain customer-owned; Python is only the existing thin CI evidence surface. Fork execution has read-only token/ephemeral hosted job and no service secret. Customer code may interfere with its own job; metadata is reproducibility evidence, not attestation.

Future paid review (P3): use a minimal authenticated GitHub App page displaying one changed-contract inventory and exact revision approval. Stable installation/repository/reviewer IDs are authority; names are labels. Minimal installation permissions are metadata read, contents read, pull requests read, actions read and checks write; no code/issue/comment write. Validate this actual API route in P3, especially private/fork access. No App code or server is implemented here.

Trusted base policy declares explicit spec/fixture/baseline/workflow/build/policy path sets and suite selection. Build a canonical sorted inventory of base/proposed file pairs (old/new path, status, old/new SHA256), including renames/deletions and changes to excluded selection. Hash that inventory together with policy bytes, selected suite and runner identity. A proposed policy modification is evaluated under the old base policy, never under its own weakened rules. No relevant changes can auto-satisfy review only after a complete current passing result; relevant changes require explicit approval. Requiring CODEOWNERS/GitHub reviews alone can be enough for some teams; the paid value hypothesis is consolidated exact-context review, removal/selection detection, invalidation and history across repositories, not another red/green comment. Demand and the $49 willingness-to-pay remain unvalidated.

Approval tuple: installation/repository ID, PR number, reviewer ID, verified current role, head SHA, base SHA, tested SHA, policy digest, inventory digest, runner/suite digest, run ID/attempt and artifact ID/digest. Team default excludes author; explicitly configured personal self-review is labeled. Recheck role before applying approval. Any tuple change, newer run attempt, relevant base update, policy/selection change or membership revocation invalidates old satisfaction. Conservative invalidation on unknown base changes is preferable to stale success. Updating a baseline requires committed reviewed bytes and a new passing result; approval never modifies Git content or overrides a red execution check.

Future state machine follows [04](../plans/04-github-execution-and-review.md): awaiting run → evaluating → tests failed / awaiting review / satisfied; head/base/attempt change → superseded; malformed/missing/expired metadata, entitlement/API failures → unavailable with five durable retries within 15 minutes; uninstall → removed. Never green on absence. P3 must test API publication/reconciliation, same/fork/private tenant binding, hostile archive envelopes, changed policy and permission revocation. No user-maintainer outreach or marketing is needed for this batch.
