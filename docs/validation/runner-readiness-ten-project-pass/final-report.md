# Runner readiness: first ten-project engineering batch

The private candidate is `v0.4.0-rc.5`, production source
`129b7a45c0006be550f798ce52c2fbbfd327e515`. The completed scope is the first ten
new-project runner batch, plus ten old-project migrations. The
[closing admission receipt](campaign-admission.json) is the authority for final
gate status; intermediate receipts intentionally retain their earlier zero
overall-admission fields. The remaining 90 projects, real beginner study,
publication and paid-product qualification have separate gates.

Public spec/report v3 adds selected same-execution file bytes, absence, directory,
empty-directory and exact-entry assertions. Checks run before workspace teardown
and carry invocation/workspace identities. Recording supports capture, review,
fresh replay and export; selective maintenance preserves unrelated approved
expectations. Failed captures cannot silently disappear into a successful export,
and an input-only draft cannot claim completion. Public schemas, examples,
migration notes and reports describe the new contract; older strict formats
remain distinct. No AI or target-framework branch was added to the Go runner.

General measured repairs include native Unix signal-status normalization,
Windows interrupt inheritance and resize observation, bounded Unix device-attribute
replies, exclusion of reserved row-snapshot data from directory test discovery,
useful final alternate-screen failure evidence, and a shared bounded step budget
that accommodates real saved-state workflows. Before/after regressions, first
failures and requalification are retained in the [requirements register](requirements.md).

false green the new contract addresses. Papis preserves its initially missed
