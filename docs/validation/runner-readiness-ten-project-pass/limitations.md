# Remaining limits and risk dispositions

This is a private ten-project engineering qualification of rc.5, with frozen
production source `129b7a4`. It is not a stable release or the completed
100-project program. Human study participants: zero; paid-product admissions:
zero. Publication, outreach and new pull requests were not performed.

- Historical Windows wizard, macOS readiness/exit and fixture exit-8 incidents
  retain their original failed evidence. Bounded current-control repetitions
  passed; those observations do not establish the original causes.
- fff's original Linux quit timeouts remain unexplained. Separate original E03
  and E11 investigations each observed 150 current Linux passes; the
  [E11 observations](fff/r3-e11-batch-observations.json) preserve that limited
  disposition. The two original final-series failures remain counted. The
  macOS segmented-DEL rename failure has an input-segmentation correction;
  printable text segmentation preserves control groups. Neither correction nor
  later green series erases the failed original series.
- Windows snapshot-maintenance rename returned access denied twice in historical
  fixture setup. Focused passes and a later complete suite do not explain that
  original error. There is no claimed atomic-write repair for it.
- Superfile and Glow Windows remain excluded after actual upstream terminal-buffer
  races were reproduced on their original pins. Their qualified paths are Linux
  and macOS. Hosted Windows short-path alias creation remains unqualified.
- Compatibility applies to the exact [native project/host matrix](native-compatibility.md),
  synthetic terminal controls and reviewed workflows. It does not cover arbitrary
  frameworks, complete application behavior, styling/grapheme fidelity, mouse,
  clipboard, remote services, plugins, all shell environments or other architectures.
- Prepared agent routes exclude target acquisition/setup and involve an operator
  familiar with the tool. Initial Plop, Poetry and Rclone counting targets were
  missed. The [authoring assessment](usability-assessment.md) preserves them;
  five unused participant sheets establish no human usability result.
- The delivered CI triplet used a source-built binary at the frozen source.
  It proves actual dispatched success, saved-state failure and recovery, not a
  real same-repository/fork pull-request event or use of the archive bytes in that
  triplet. Archive identity is established by the separate native matrices.
- Linux offline execution uses a process-scoped socket-denial control. macOS and
  Windows offline network denial were not claimed. Trusted target execution,
  PTYs and managed workspaces provide no security sandbox or general isolation.
- Storage figures are periodic logical-byte observations, not OS quotas or exact
  peaks. Earlier Bundler retained evidence temporarily exceeded its project cap;
  corrected compaction restored the bound. An early Go module-cache write outside
  the workspace is preserved and was not deleted; strict workspace-only acceptance
  is rejected for those historical attempts. The later PowerShell cache escaped
  its campaign subdirectory while remaining inside the repository; exact bytes
  were retained, checked removal and an owned-path prevention control passed.
- Historical successful workflows with incomplete manifests, hidden fixtures,
  missing cleanup or the wrong phase retain zero qualification credit. The final
  audit does not retrospectively repair them. Edit Windows rebuild bytes differed;
  source restoration and each executed binary were independently identified,
  without a Windows byte-reproducibility claim.
