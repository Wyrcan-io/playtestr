## Build and execution boundary

The documented build is `./configure` then `make`; the tracked `GNUmakefile` provides GNU make compatibility for the BSD-style makefile. `configure` performs bounded compiler/link probes for curses, optional compatibility APIs, and writes only `config.h`, `config.mk`, and `config.log` in the source tree. It uses `mktemp` for one temporary probe. The reviewed build has no download, package-install, privilege, or service hook. The pinned application requires a working C compiler, GNU make, and a native curses/terminfo development library.

The upstream test target builds `pick` and a PTY test helper, then runs the pinned shell test cases. The helper opens a real PTY, makes it the child controlling terminal, feeds reviewed key sequences, and waits for the child. Tests create temporary files with `mktemp`, compare output, and remove their own paths. Campaign runs will direct `TMPDIR` to an owned campaign directory, cap process time/output, and retain exact test logs. The target has no network or live-service requirement.

The public usage intentionally supplies choices as a data stream and uses the controlling terminal for interactive keys. In scenarios the launch adapter will use the documented shell redirection form (`exec pick < choices.txt`) so `pick` itself replaces the shell and reads a frozen workspace fixture on standard input while obtaining keystrokes from its controlling PTY. The shell performs only this ordinary stream-redirection plumbing; it contains no assertions or target behavior. The test oracle is the selected line visibly emitted by `pick` on the PTY after curses teardown. Pick's `filter_choices` scores `choice.string`, not `choice.description`; description selection is checked by navigating duplicate labels and observing the rendered/emitted description, not by querying description text. Pick does not persist application state, so it contributes no saved-file-state coverage.

The native build helper retains configure and upstream-test logs, installs the owned binary, then invokes the reviewed upstream `cleandir` target and confirms the acquired source file map has been restored byte-for-byte before any Playtestr scenario starts. Test temporary files use the campaign-owned `TMPDIR`; source build products do not remain mixed with pinned source identity.

Linux and macOS are selected native hosts according to the screening and compatibility declarations. The exact acquisition hash and native build evidence are retained in the hosted attempt artifacts. The first native attempt stopped before build on an overstrict archive-entry check. The second native attempt built Pick, passed its upstream suite, and installed the exact rc.7 runner on both hosts, but the harness rejected its undeclared phase before launching Pick. The third attempt passed native builds, upstream tests, candidate installation, exact source cleanup, and storage checks. It launched twenty development cases across the two hosts: 18 passed; Linux N08 failed because its contract lacked an explicit target-exit action, and macOS E04 timed out because the scenario queried description text instead of navigating duplicate labels. Both failures and all reports remain in the immutable attempt receipt. Scenario declaration v3 fixes these observations and has not yet launched.
